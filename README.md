# LLM-Eval-Lab

大模型、Agent 与 RAG 评测工程学习项目。

## 项目背景

做这个项目是因为一个很实际的问题：选模型的时候，厂商公布的跑分不能直接信。那些分数是在人家的题目上测的，跟自己真正要用的场景不一定对得上。真要花钱买 API，或者把在用的模型换成新版本，总得先拿自己的题测一遍才敢定。

所以这个项目就是做一套自己的评测：题目自己攒，评分尽量做到可复核，最后给一个明确的结论，到底选哪个模型、为什么。

场景先定下来，不然测出来的分数没法用。假设一个小团队要找一个模型干三件事：中英文技术支持问答占一半，简单的代码辅助占三成，剩下的两成是专业知识问答。要求也先说死：技术支持类的题 pass@1 至少 80%，代码题至少 60% 能通过测试，慢的不行（P95 延迟 5 秒以内），贵的也不行（平均一次调用别超过 2 分钱）。先按这个门槛筛一遍，剩下的再比价格和速度。这样最后写报告的时候能说清为什么选 A 不选 B，而不是把分数列个表就完了。

题目分开发集和测试集，调东西的时候只用开发集，最后结论看测试集，免得自己骗自己。评分用了三种办法：能用规则判的用规则，代码题跑测试，剩下的用模型判，再人工抽查对一遍，看模型判得准不准。

最后要交的东西就两个：一份选型报告（几个模型的质量、延迟、价格放一起比，给结论），还有一套能重复跑的回归测试，模型升版或者改提示词的时候重跑一遍，看有没有变差。

配套的 RAG 项目是 gitlab-handbook-rag，拿 GitLab 的公司手册做知识库问答。那边是真应用，这边是评测和选型的方法，正好配成一对。
